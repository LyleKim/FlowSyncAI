# FlowSyncAI UX 리디자인 — 공유 컨텍스트

모든 UX 작업의 출발점. 서브에이전트는 이 파일을 먼저 읽는다.

## 프로젝트
- 팀 프로젝트용 태스크 트래커(Django + React/TS/Vite/Tailwind4). 자세한 건 `README.md`, `CLAUDE.md`, `docs/DECISIONS.md`.
- 현재 브랜치는 UI/UX 리디자인용. **이 단계(UX 전략·구조)에서는 제품 코드(`frontend/`, `backend/`)를 수정하지 않는다.** 산출물은 `docs/ux/`에만 쓴다.

## 사용자 (확정)
- 팀원 2~10명. 각자 PR을 올리고 서로 리뷰한다.
- 인증 없음(현재). GitHub 감시 레포(`WatchedRepo.githubLogin`)와 PR 자동 동기화가 이미 있다.

## 핵심 목적 (사용자가 직접 말한 것)
1. **내가 리뷰어로 지정된 GitHub PR이 올라오면 추적해서 "할 일"에 추가**한다. 나는 그 작업을 확인하고 리뷰를 진행한다. 참여하는 모든 팀원이 각자 이렇게 쓸 수 있어야 한다.
2. **나와 직접 상호작용이 없는 프로젝트의 다른 부분(= 기능 영역별)의 진행 상황**을 **추상화된 개념**으로 파악할 수 있어야 한다. 목적은 프로젝트 전체 흐름 이해. **말로만 쓰는 게 아니라 시각화 요소가 필수.**
3. 현재 UI는 "AI 슬롭" 느낌이 강하다. 디자인과 사용자 경험을 모두 다시 고려한다.

## 윤리·제약 가정 (확정)
내부 협업 도구, 규제 대상 아님, 취약 계층 대상 아님, 사용자 데이터 최소 수집, 조작적 패턴 전부 거부.

## 현재 UI 진단 요약 (코드 리딩 기반, 미렌더링)
UX 건강 점수 약 42/100. 안티패턴(조작)은 없음, 장식 과다.
- P0: "나" 개념 없음(`assigneeId`는 자유 문자열, "내 것" 필터 없음). 프로젝트 전체 흐름 화면 없음(분석 탭은 팀 2~10명 규모에 의미 없는 통계).
- P1: IA가 기능 나열(칸반/모든 작업/분석/아키텍처 동급, 칸반·리스트는 같은 데이터의 중복 보기). PR이 일반 태스크와 동급 취급(9px 보라 `PR` 뱃지뿐, 대기 시간·요청자·변경 규모 없음). 접근성 속성이 칸반·사이드바·모달에 없음(`aria-`/`role`은 `architecture/*`와 `WatchedReposPanel`에만 있음 — 03 인벤토리로 정정됨; 모달은 role/Esc/포커스 트랩 없음; 10px 이하 텍스트 48곳). 활동 피드는 `localStorage` 전용(백엔드 `ActivityLog`는 있으나 엔드포인트 없음).
- P2: 용어 혼재("모든 작업"/"작업 대장", "검토 중"/"리뷰"), 오류·빈 상태 문구가 기술 용어 위주, 디자인 토큰 없음(slate 유틸리티 직접 사용).
- 슬롭 요소: `v1.0.0 Stable` 가짜 버전, `긴급 🔥`, 우선순위별 색 좌측 굵은 테두리+컬러 그림자, 컬럼마다 설명문, Sparkles 아이콘.
- 지킬 것: 감시 레포+PR 자동 동기화, `hasUnreflectedReview`(서버 계산), 아키텍처 페이지의 "그룹별 변경 흐름" 시각화(핵심 목적 2의 씨앗), `role="status"` 토스트·`focus-visible`.

## 관련 코드 위치

## 확정된 결정 (사용자 승인, 2026-11-24)
1. **"나"**: 브라우저(localStorage)에 내 GitHub 로그인을 저장해 식별한다. 인증은 이번 범위 밖.
2. **다중 리뷰어 PR**: 리뷰어마다 각자의 "내 할 일"로 보인다(PR × 리뷰어).
3. **기능 영역**: 코드 디렉터리 기준 아키텍처 그룹으로 자동 생성하고, 팀이 이름을 붙이거나 묶을 수 있게 한다. PR 변경 파일을 같은 그룹으로 매핑해 PR/Task와 연결.
4. **정리**: AI 체크리스트는 보조 기능으로 강등(삭제 아님). 분석 탭 폐기, 칸반·리스트 통합, 활동 피드(현재 렌더되지 않는 죽은 코드)와 localStorage 오프라인 폴백 정리. 아키텍처(영역 흐름) 화면은 승격.
5. 시각화는 영역별 활동 흐름(A안)으로 시작하고 "리뷰 대기 PR 수·최장 대기"를 얹는다. LLM 서사(C안)는 제외.

### 추가 확정 (화면 계획 질문 일괄: 사용자 "추천대로")
36. 시각 방향 `10-visual-direction.md`("관측 기록지", Pretendard 자가 호스팅 번들, "리뷰 중" 청록색, 시스템 설정 기본 테마)를 **채택**. 단 이 방향은 Impeccable이 사용자 선택 화면 없이 배정한 후보이므로, 토큰 실제 값을 코드에 적용하기 전(구현 시 시각 디자인 태스크)에 사용자가 렌더링 결과를 보고 재검토할 수 있다. `PRODUCT.md`(repo 루트)는 인터뷰 없이 추론한 문서라 커밋 전 검토 필요.

39. 내 리뷰 요청: PR 카드에 작성자 표시, 제목 줄에는 한 줄 요약만 두고 레포별 실패 상세는 실패가 있을 때만 바로 아래에 펼침, 영역 요약은 첫 레포만(레포 이름 표시), 사이드바에 실제 대기 건수 배지(0이면 숨김).
40. 설정: 로그인 후보 엔드포인트 추가 안 함(레포 `githubLogin` 칩만), 테마에 "시스템 설정 따르기" 모드 추가, 로그인 변경은 즉시 저장 + 10초 되돌리기.
