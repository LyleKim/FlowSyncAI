# 10. 시각 디자인 방향 (Impeccable)

입력: 00(확정 결정 1~35), 01, 03(슬롭 목록), 04, 06(와이어프레임·영역 흐름 시각화 명세), 07(접근성), `docs/superpowers/plans/2026-11-24-frontend-foundation.md` Task 3(토큰 이름). 산출: 이 문서와 repo 루트 `PRODUCT.md`. **제품 코드는 건드리지 않았다.**

**진행 방식 고지**: Impeccable은 PRODUCT.md가 없으면 concept-seed를 굴리지 못한다. 답할 사용자가 없는 하위 작업이라 인터뷰 대신 00~07의 확정 사실만으로 PRODUCT.md를 썼고(추론 항목은 파일에 그렇게 표시), `concept-seed --mode operate`는 후보 7개 중 **3번째 방향을 짓도록** 배정했다. 결정 화면(serve-question)으로 사용자에게 고르게 하는 단계는 하지 않았다. 대신 §0 끝에 사용자 결정 질문으로 남겼다. 렌더 확인은 없다(코드가 없음). 대비비는 §3의 스크립트로 실제 계산했다(스크립트는 scratchpad에만 둠).

## 1. 디자인 방향

### 1.1 한 줄

**관측 기록지(기상청 관측·예보 도표의 규율).** 흰 종이 같은 차가운 회청색 바탕, 잉크색 한 가지 청색, 가늘고 일정한 눈금선 위에 같은 척도로 찍힌 막대. 장식 없이 "읽는 숫자"가 주인공이다.

### 1.2 왜 이 앱에 이 방향인가

- **사용 장면(Operate)**: 팀원이 업무 시작 때와 중간중간 "내가 리뷰할 PR이 뭔가"를 확인하러 여는 도구. 한 번에 몇 초. 화려함이 아니라 **다시 열어도 같은 자리에 같은 모양**이 있는 신뢰가 가치다.
- **제품의 진짜 메커니즘**: (1) 대기 시간이 있는 줄 세운 큐, (2) 영역별 활동을 같은 눈금으로 비교하는 작은 다중 차트(06 §4.1). 둘 다 "측정값을 같은 척도로 늘어놓고 읽는" 일이다. 일기도·관측표가 오래 쌓아 온 어휘(고정 눈금, 관측치 vs 잠정치, 결측 표시)가 그대로 맞는다.
- **조작 거부 원칙과 일치**: 관측표는 겁주지 않는다. 오래 기다린 PR은 빨강·불꽃이 아니라 큰 숫자와 굵기로 말한다(06 §3.1, 05 §2).
- **정직한 지표**: 관측 도표에는 "결측"과 "0"을 구분하는 관습이 있다. 06의 "0과 모름 구분", "이번 주는 속이 빈 막대"가 외부 은유가 아니라 이 세계의 문법이 된다.
- **세계가 빌려주는 것은 네 가지뿐**(Operate 규칙): 활자, 팔레트, 밀도, 서명 동작 하나. 내비·컨트롤은 표준(사이드 내비, 버튼, 표, 입력). 일기도 모양의 등압선·구름 일러스트·지도는 쓰지 않는다(의상이 된다).

### 1.3 서명 동작 (한 가지)

**관측 눈금.** 모든 영역 행의 막대가 **같은 고정 눈금**(1칸 = 커밋 2개, 최대 8칸)을 쓰고, 행 뒤에 점선 눈금선(4칸마다)이 깔린다. 이번 주(집계 중)는 **속이 빈 막대**, 모름은 **점선 막대**, 0은 **바닥선뿐**. 대기 시간은 7칸 한도의 **칸 막대**(1칸 = 1일). 이 세 가지가 같은 문법(칸 단위, 같은 높이 격자)이라 화면 전체가 하나의 기록지처럼 읽힌다. 상세는 §6.2.

### 1.4 후보 7개와 배정 (고지)

일기도 후보를 3번에 둔 것은 내 순서에 배정 번호를 맞췄다는 점을 숨기지 않는다. 순서는 "이 앱의 메커니즘에 공명하는 정도"로 매겼고, 1·2위도 방향으로 충분히 성립한다. 아래는 비교용이다.

| # | 세계 (그래픽·인쇄 전통) | 이 앱과의 공명 | 비고 |
|---|---|---|---|
| 1 | 지하철 노선도 | 영역 = 노선, 흐름 = 구간 | 영역 연결 구조 데이터(결합)는 있지만 위치·순서 정보가 없어 지도가 거짓 구조를 만든다 |

## 2. 타이포그래피

### 2.1 폰트 (외부 CDN 없음, 결정 20)

| 용도 | 선택 | 근거 |
|---|---|---|
| UI 전체 한 가족 | **Pretendard Variable**(SIL OFL, 상용 포함 자유 사용·재배포) **자가 호스팅** | 한글·라틴이 같은 두께 곡선으로 설계됨, 가변 굵기, `tnum`(고정폭 숫자) 지원. 제품은 숫자(대기 일수·건수)가 핵심이라 숫자 정렬이 중요 |
| 폴백 | `"Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", system-ui, sans-serif` | 폰트 로드 실패·오프라인에서도 한글이 시스템 고딕으로 깨끗이 나옴 |
| 코드·경로 | `ui-monospace, "SF Mono", Menlo, Consolas, monospace` 시스템 스택만 | 경로·PR 번호 줄 등 실제 코드 값에만. 숫자 장식에 쓰지 않음(03의 `font-mono` 26곳 장식 사용 폐기) |

- **번들 방식**: "동적 서브셋" woff2(유니코드 범위별 조각)를 repo 안 `frontend/public/fonts/`에 넣고 `@font-face`의 `unicode-range`로 필요한 조각만 로드(한글 전체 가변 단일 파일은 수 MB). 설치 경로(npm `pretendard` 패키지 또는 릴리스 파일 복사)와 정확한 용량은 구현 시 **확인 필요**(내가 설치해 보지 않았다). `font-display: swap`, 폴백 스택이 먼저 보여도 줄바꿈이 크게 달라지지 않도록 `size-adjust`는 구현 단계에서 측정해 정한다.
- 디스플레이 서체를 따로 두지 않는다. Operate에서는 한 가족이 제목·라벨·본문·데이터를 모두 맡는 것이 맞다.

### 2.2 크기·굵기·행간 (plan Task 3의 6단계에 값 부여)

| 토큰 | 크기 | 행간 | 굵기 | 쓰는 곳 |
|---|---|---|---|---|
| `--text-caption` | 12px (0.75rem) | 1.5 | 400/500 | 보조 표기("PR 생성 기준"), 막대 축 힌트. **핵심 정보 금지** |
| `--text-body-sm` | 14px (0.875rem) | 1.5 | 400/600 | 메타 줄, 표 셀, 버튼, 칩, 입력 힌트 |
| `--text-body` | 16px (1rem) | 1.6 | 400/600 | PR 제목, 설명 문단, **대기 N일** |
| `--text-title` | 20px (1.25rem) | 1.4 | 600 | 섹션 제목(h2), 요약 보조 |
| `--text-heading` | 24px (1.5rem) | 1.3 | 600 | 화면 제목(h1) |
| `--text-display` | 30px (1.875rem) | 1.2 | 700 | 큐 요약 숫자 "대기 4건"의 숫자 한 곳 |

- 단계 비율 약 1.17~1.25. 12→14→16→20→24→30. 12px 미만 0건(07 §2.5: 9·10·10.5·11px 전부 폐기). 기본 UI 글자는 14px, 읽는 글(PR 제목·설명)은 16px.
- **굵기는 400 / 600 / 700만.** 03에서 거의 모든 텍스트가 bold 이상이었다. 한 영역 안에서 600은 "읽기 시작점"(대기 시간, 제목) 한두 군데에만 쓴다. 700은 display 숫자 한 곳.
- **한글 규칙**: `html { lang: ko }`, `word-break: keep-all`(어절 단위 줄바꿈), 경로·URL·긴 영문은 `overflow-wrap: anywhere`. 한글 본문 자간은 0 유지(`letter-spacing` 음수는 20px 이상 제목만 -0.01em). 본문 줄 길이는 읽는 글에서 한글 약 35~40자(`max-width: 38em` 정도) 안팎(07: 설명 앞부분 등).
- **숫자**: 대기 시간·건수·막대 값에 `font-variant-numeric: tabular-nums`(Pretendard `tnum`)로 열이 맞는다. 단위("일", "건")는 숫자 뒤에 같은 굵기로 붙이고 숫자와 단위 사이는 좁게 붙인다(`4일`).
- 크기는 `rem`. 200% 확대·텍스트 간격 확대에서 고정 높이로 자르지 않는다(07 §2.5, 03의 `h-[19.5rem]` 폐기).

## 3. 색 체계

### 3.1 원칙

1. **차가운 회청색 중립 + 잉크 청색 하나.** 청색은 "지금 선택/주 행동/링크/막대" 이외에 쓰지 않는다. 보라·분홍·그라데이션·영역별 색 없음.
2. **의미색은 의미 하나에만, 항상 글자·글리프와 짝**(07 §2.4, 결정 16의 사실만 말하기). 색을 지워도(그레이스케일) 상태·우선순위·추세가 읽혀야 한다(07 #36).
3. **텍스트에는 어두운(라이트)·밝은(다크) 변형만** 쓰고 채움에는 연한 `*-subtle` 배경을 쓴다(07 §2.5 "상태 색은 텍스트에는 어두운 변형").
4. 03 §2.1의 "보통 = amber = 검토 중" 같은 색 의미 충돌을 풀기 위해 **색을 의미에 1:1로** 재배정한다(아래 표).
5. 라이트·다크는 같은 구조의 두 세트이며 `html.dark` 한 곳에서 바뀐다(plan Task 3). 첫 값은 시스템 설정(`prefers-color-scheme`)을 따른다.

### 3.2 의미 배정

| 의미 | 색 | 글자(필수) | 글리프(필수, 형태가 다름) |
|---|---|---|---|
| 상태: 할 일(`todo`) | 슬레이트 | "할 일" | 빈 원 ○ |
| 상태: 진행(`inprogress`) | 잉크 청색 | "진행 중" | 반원 ◐ |
| 상태: 리뷰 중(`review`) | 청록 | "리뷰 중" | 겹친 원 ◎(또는 눈 모양 라인 아이콘) |
| 상태: 완료(`done`) | 녹색 | "완료" | 체크 원 ✓ |
| 우선순위 낮음/보통/높음/긴급 | 슬레이트 / 본문색 / 황갈 / 적색 | "낮음/보통/높음/긴급" | 눈금 1~4칸(▁▃▅▇ 계열의 그린 막대 4칸 중 n칸 채움) |
| 위험/오류 | 적색 | 문장 | 삼각 경고 아이콘(라인) |
| 주의(오래됨·잘림) | 황갈 | "오래됨", "일부만" | 삼각 느낌표 대신 **시계 아이콘**(오류와 모양 구분) |
| 성공 | 녹색 | "정상" | 체크 |
| 선택/현재 위치 | `--accent-subtle` 채움 + 굵기 600 + `aria-current` | 라벨 | (없음, 굵기 변화로 색 제거해도 구분) |

글리프는 lucide(이미 의존성)의 라인 아이콘이거나 4~5줄짜리 인라인 SVG, 16px·stroke 1.75 한 규격. **이모지·유니코드 기호를 아이콘 대신 쓰지 않는다**(위 ○◐◎✓는 설명용이고 실제는 SVG).

## 4. 간격·모서리·그림자·모션

### 4.1 간격

4px 격자. **허용 값: 4, 8, 12, 16, 24, 32, 48** (Tailwind `1,2,3,4,6,8,12`). 소수 단계(`1.5`, `2.5`)와 임의값(`19.5rem`, `22px`) 금지(03 §2.5).

| 맥락 | 값 |
|---|---|
| 테두리·배경이 있는 컨테이너의 안쪽 여백 | **최소 12px, 기본 16px**(훅의 padding 지적 대응, §8) |
| 목록 행 | 상하 12px, 좌우 16px. 행 사이 구분은 1px `--border` 가로선(간격이 아니라 선) |
| 패널·배너 | 16px(작은 폭 12px) |
| 같은 그룹 요소 간격 | 8px, 서로 다른 그룹 24px, 섹션 사이 32~48px |
| 제목 위가 아래보다 크게 | h2: 위 32 / 아래 12 |
| 터치·클릭 타깃 | 최소 24px(07 #41), 아이콘 버튼·닫기·영역 칩 44px 영역(시각은 작아도 패딩으로 확보) |
| 고정폭 | 사이드바 224px(데스크톱), 대기 열 96px, 본문 최대 폭 960px(큐), 영역 표 1120px |

### 4.2 모서리

`--radius-sm: 4px`(버튼·입력·칩·막대 윗모서리 0~2px), `--radius-md: 8px`(패널·배너·대화상자·행을 담는 목록 래퍼). 이 둘뿐. 알약(pill) 완전 둥근 모양, `rounded-2xl` 이상 없음. 행 자체는 모서리 없음(래퍼가 8px).

### 4.3 그림자·깊이

- **카드·행·배너는 그림자 없음.** 구분은 1px `--border`와 표면 색차(`surface` vs `surface-raised`)로 한다.
- **`--shadow-overlay` 1종**: 대화상자·팝오버·토스트만. 오프셋 있는 중립 그림자(색 없음).
  - 라이트: `0 8px 24px rgb(15 23 42 / 0.14), 0 1px 3px rgb(15 23 42 / 0.10)`
  - 다크: `0 8px 24px rgb(0 0 0 / 0.5), 0 1px 3px rgb(0 0 0 / 0.4)` + 1px `--border-strong` 윤곽(다크에서 그림자만으로는 안 보임)
- 컬러 그림자(`shadow-blue-*` 등 03의 20여 곳), `backdrop-blur`, 링 4px+`scale-110`: 전부 폐기.

### 4.4 모션

- 모션은 **상태를 전달할 때만**. 기본 `150ms`, `cubic-bezier(0.22, 1, 0.36, 1)`(ease-out). 대상은 `background-color`, `color`, `border-color`, `opacity`. `transition-all`(03에서 37곳) 금지, 레이아웃 속성 애니메이션 금지.
- 행 펼침/접힘: 높이 애니메이션 없이 즉시(내용이 바뀌는 중에도 위치가 안 흔들림). 펼침 토글 아이콘 회전 150ms만 허용.
- 동기화로 행이 다른 그룹으로 이동: 이동 모션 없이 새 위치 행의 배경을 `--accent-subtle`로 두었다가 1.2초 동안 `surface-raised`로 되돌림(06 §3.5 "색·윤곽 변화"). 포커스는 옮기지 않는다.
- 스피너: 14px 선 회전 하나(확인 중일 때만). `prefers-reduced-motion: reduce`에서는 회전 없이 정적 아이콘 + 글자 "확인 중…". `animate-pulse/ping/bounce`, 페이지 진입 연출 없음.
- `@media (prefers-reduced-motion: reduce)`에서 모든 transition `0.01ms`(plan Task 3 테스트 (c)와 일치).

### 4.5 슬롭 요소 대체표 (03 §4 대응)

| 슬롭 | 대체 방식 |
|---|---|
| `긴급 🔥` 등 이모지 6곳 | 글자 "긴급" + 눈금 4칸 글리프(§3.2). 이모지 0건 |
| 우선순위별 색 좌측 굵은 테두리 + 컬러 그림자 | 테두리·그림자 둘 다 제거. 우선순위는 행의 **메타 줄 앞 글자+눈금 글리프**로. 강조는 `--accent-subtle` 배경이나 선택 시 1px `--accent` **전체 테두리**(한쪽 막대 금지) |
| 컬럼 설명문(칸반 열마다 한 줄 설명) | 열 머리는 `이름 · 건수`만. 설명은 필요한 한 번의 첫 사용 빈 상태 문구(§6.5)와 접근 이름(`aria-label`)으로 옮김. 상시 노출 설명문 없음 |

| 카드 호버 `-translate-y`, 호버 전용 버튼 노출 | 호버로 위치·노출이 바뀌지 않음. 호버는 배경 `--surface-sunken`만 |
| 아이콘이 텍스트를 반복(03 §4의 Calendar, Eye 등) | 아이콘은 글자가 말하지 않는 것을 더할 때만(상태 글리프, 외부 링크 표시, 펼침 방향). 나머지 삭제 |

### 6.1 큐 행 (내 리뷰 요청)

- 래퍼: `ul`, `surface-raised`, 1px `--border`, `radius-md`, 내부 `overflow: hidden`이 아닌 **행 자체가 `radius` 없음**(오버레이가 잘리지 않게).

- **제목 열**: PR 제목 16px/600 `--text`(h3, 줄바꿈 허용 2줄 후 말줄임 금지: 길면 그대로 줄바꿈), 메타 줄 14px muted: `레포 #번호 · 작성자 · +120 −30 · 5파일`(+/−는 글자, 색 없음, sr 텍스트로 풀어 읽기), 영역 칩 최대 2개 + "외 N"(14px, 1px `--border-strong` 윤곽, `radius-sm`, 44px 클릭 영역, 영역은 색 없음).
- **행동 열**: `GitHub에서 리뷰` 텍스트 링크형 보조 버튼(14px/600, `--accent`, 외부 링크 아이콘 16px, 밑줄은 호버/포커스에서만이 아니라 **항상 `text-underline-offset: 3px`로 얇게**), 펼침 토글은 아이콘 버튼 44px 영역.

- 상태: 호버 = 배경 `--surface-sunken` 40% 정도(`color-mix`), 포커스 = 2px `--focus-ring` + 2px 오프셋, 선택 없음(큐는 선택 개념 없음), 로딩 = 같은 격자의 스켈레톤 행(막대 모양 `--surface-sunken`, 애니메이션 없음, 정적), 오류 = 행 위가 아니라 목록 위 배너.
- 모바일(390): 대기 열이 제목 위 한 줄로(`4일 · PR 생성 기준`), 행동 버튼 전체 너비, 터치 타깃 44px.

### 6.2 영역 행 차트 (서명 동작)

한 행 = 한 영역(네이티브 `table`, 06 §4). 열: 영역(이름+경로) / 주간 활동 / 추세·마지막 변경 / 리뷰 대기.

- **막대 묶음**(5주 기준, 06 §4.2): 가로 5개 × 12px 폭, 막대 간 4px = 76px. **세로 격자 = 5px/칸**, 1칸 = 커밋 2개, 8칸(40px)에서 자름. 막대 값은 올림(1커밋 = 1칸). 막대 색 `--chart-bar`, 윗모서리 0(칸 단위로 끊어 읽히게), 같은 영역 안의 5개 모두 같은 색 한 가지.
- **바닥선**: 1px `--border-strong`(막대 폭 전체 연장).
- **눈금선**: 4칸(8커밋)과 8칸(16커밋) 높이에 1px 점선 `--chart-grid`, 행마다 같은 높이라 행 사이를 눈이 건너 읽는다. 눈금 숫자는 행에 쓰지 않고 표 위 범례에 한 번("점선 하나 = 커밋 8개").
- **이번 주(집계 중)**: 속이 빈 막대 — 1.5px `--chart-bar` 윤곽, 안쪽 비움(투명). 범례에 "속이 빈 막대는 이번 주(아직 집계 중)". 이 문구의 최종 단어는 `/articulate` 몫.
- **0**: 막대 없음, 바닥선만. **모름**: 점선 윤곽 2칸 높이 막대(`--border-strong` 1.5px dashed).
- **높이 확보**: 막대 영역 고정 높이 40px + 아래 주 라벨 없음(상세에서 주 시작일). 행 높이는 최소 64px.
- **접근성**: 묶음에 `role=img` + `aria-label`("5주 커밋: 4, 6, 10, 14, 16개(마지막은 집계 중)"), 색 없이도 모든 값이 텍스트로 존재.
- **대기 칸 막대**(영역 최장 대기): 7칸 × 10px 폭, 칸 사이 2px, 높이 8px, 채운 칸 수 = 일수(올림, 7일 이상은 7칸 채움 + 글자 "7일+"). 채움 `--chart-bar`, 빈 칸은 1px `--border-strong` 윤곽. 옆에 글자 `최장 4일`(14px/600). 막대는 장식이고 같은 값이 글자로 있다.
- **정체 후보 신호**(규칙은 유지, 결정 23): 행 안 한 줄 사실 문구 `리뷰 대기 중, 활동 없음`(14px/600 `--warning` + 시계 아이콘). 배지·행 배경색 없음. 정렬로 맨 위에 올리지 않음.
- **행 헤더**: 영역 이름 16px/600(주 링크), 아래 14px muted 원래 경로(`font-mono` 시스템 스택, 13px 아님: 14px). 비대 영역 경고는 muted 한 줄 + 경고 아이콘.
- **표**: 머리글 14px/600 muted, 배경 `--surface-sunken`, 행 구분 1px `--border`. 셀 안쪽 12px/16px.
- 반응형: 768 이하 카드형, 막대 눈금(5px/칸)은 줄이지 않는다(06 §4.6).

### 6.3 상태 라벨

- 형태: 글리프 16px + 글자 14px/600, 같은 줄, 간격 4px. **배경 채움 없음, 알약 없음.** 색은 `--status-*`(글자와 글리프에만).
- 글리프는 모양이 서로 다르다(빈 원 / 반원 / 겹친 원 / 체크 원).
- PR 항목(수동 변경 불가, 결정 12): 같은 라벨에 muted 추가 문구 `GitHub 기준`(14px). 이동 컨트롤 없음.
- 수동 작업: 라벨이 `select`/`radiogroup`으로 바뀌는 곳은 같은 글리프+글자를 보이게 하고 윤곽 1px `--border-strong`으로 "누를 수 있음"을 표시.
- 우선순위 라벨(§3.2): 눈금 4칸 글리프(채운 칸 수=등급) + 글자. 긴급도 빨강 텍스트 + 글자 "긴급"일 뿐 테두리·불꽃 없음.

### 6.5 빈 상태

## 7. 레이아웃 뼈대 (참고)

- 데스크톱: 좌측 내비 224px(`surface-raised`, 우측 1px `--border`) + 본문 `surface`. 내비 항목 높이 40px, 현재 위치 = `--accent-subtle` 채움 + 600 굵기 + `aria-current`(06 §1). 큐 배지는 숫자 글자(14px/600, 윤곽 1px `--border-strong`), 색 채움 없음.
